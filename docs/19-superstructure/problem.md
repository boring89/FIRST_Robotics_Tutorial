# 各做各的問題

--8<-- "alpha-warning.md"

## 這頁學什麼

- 第 8 章的按鈕配置在比賽中會出什麼問題
- 為什麼「每個機構都會動」還不等於「機器人能打比賽」
- 協調好幾個機構時，程式要負責哪些事

## 觀念

### 第 8 章的按鈕

第 8 章最後的 `RobotContainer` 裡（手臂的按鈕在 [Motion Profile](../08-control/motion-profile.md#範例) 那頁加上），每個機構都有自己的按鈕：

| 按鈕 | 做什麼 | 用到的機構 |
| --- | --- | --- |
| `faceDown`（按住） | 吸入，拿到物件就停 | Intake |
| `faceRight`（按住） | 吐出 | Intake |
| `rightBumper`（按一下） | 飛輪加速後送料 | Intake、Shooter |
| `faceUp` / `faceLeft`（按一下） | 手臂轉到發射角度 / 收起 | Arm |
| 右搖桿上下 | 手動控制手臂 | Arm |

在練習場上一個一個試，每個按鈕都沒問題。但上場比賽時，駕駛要一邊開車、一邊被對手推，同時操作這些按鈕，問題就出來了。

### 問題一：條件沒有被保證

發射需要「手臂在發射角度」，但 `ScoringCommands.shoot()` 完全不管手臂：

```java
driver.rightBumper()
    .and(intake::hasGamePiece)
    .onTrue(ScoringCommands.shoot(intake, shooter));   // 手臂在哪裡都會發射
```

駕駛忘了先按 `faceUp`，物件就會從收起的手臂打出去，打到自己的機器人或地上。吸入也一樣：手臂還在上面時按 `faceDown`，Intake 轉了但根本碰不到地面。

[第 8 章小練習第 3 題](../08-control/motion-profile.md#小練習) 的 `shootWithArm()` 已經會先轉手臂，但它有一個 `withTimeout(SPIN_UP_TIMEOUT_SECONDS)`：**時間到了，不管手臂到了沒，都會送料**。等待加上時間限制是為了不要卡住，結果卻又讓條件沒被保證。

### 問題二：按鈕互相搶機構

第 8 章用右搖桿的上下控制手臂，用右搖桿的左右控制底盤轉向：

```java
arm.setDefaultCommand(arm.manualCommand(() -> -driver.getRightY() * 0.3));
new Trigger(() -> Math.abs(driver.getRightY()) > 0.2)
    .onTrue(arm.manualCommand(() -> -driver.getRightY() * 0.3));
```

駕駛轉彎時，搖桿很難完全水平推，往斜上推一點，`getRightY()` 就超過 0.2。手動控制的 Command 搶走手臂，原本「停在發射角度」的 `goToAngleCommand` 被中斷，**手臂就掉下來了**。

反過來也一樣：`shoot()` 沒有把 Arm 列在 Requirements 裡，所以發射到一半，駕駛按 `faceLeft`，手臂就會在送料的時候收起來。

### 問題三：駕駛要記順序

要發射一個物件，駕駛要依序：

1. 按 `faceUp`，等手臂轉上去
2. 按 `rightBumper`，等飛輪加速、送料
3. 按 `faceLeft`，把手臂收起來

順序錯了、或忘了第 3 步，就會頂著舉高的手臂在場上跑：重心變高容易翻車，也容易撞到場地。駕駛的腦力應該花在開車和判斷戰術上，**「先做 A、等好了再做 B」這種事應該交給程式**。

### 問題四：看不出機器人「現在」在做什麼

Dashboard 上看得到手臂角度、飛輪轉速、有沒有拿到物件，但看不出機器人現在是在「準備發射」還是「等手臂收起來」。比賽中出了問題，賽後看 log 也很難判斷當時程式卡在哪一步。

### 程式要負責的事

把上面的問題反過來，就是協調機構的程式要做到的事：

| 要做到 | 例子 |
| --- | --- |
| **保證條件** | 手臂沒到位、飛輪沒到速，就絕對不送料 |
| **一個按鈕一個意圖** | 按住 `rightBumper` 就是「我要發射」，轉手臂、加速、送料、收手臂都由程式負責 |
| **不互相搶** | 同一時間只有一個地方在決定機構要做什麼 |
| **看得到現在的階段** | Dashboard 和 log 上有一個「目前狀態」可以看 |

接下來兩頁會用兩種做法達成這些事：先用已經學過的 Command 組合，再用狀態機。

## 常見錯誤

!!! bug "常見錯誤：用「多加一個按鈕」解決問題"
    發射前忘了轉手臂，就再加一個「轉手臂並發射」的按鈕；吸入時手臂在上面，就再加一個「收手臂並吸入」的按鈕。按鈕越來越多，駕駛越來越難記，而且舊的按鈕還在，問題沒有消失。應該讓**同一個按鈕**在任何情況下都做對的事。

2. 第 8 章的配置裡，還有哪些按鈕組合會讓機構互相搶，或在不對的時候動？至少找出一個上面沒提到的。

??? question "第 2 題參考答案"
    幾個例子：

    - 按住 `faceDown` 吸入時按 `faceUp`：手臂往上轉，但 Intake 還在轉。Intake 和 Arm 是不同的 Subsystem，兩個 Command 會同時執行
    - 發射時按 `faceRight` 吐出：`ejectCommand()` 需要 Intake，會中斷正在送料的 `shoot()`，物件被吐回去
    - 自動階段的 `getAutonomousCommand()` 呼叫的是 `shoot()`，沒有轉手臂。如果機器人開機時手臂是收起的，自動階段的第一發就會打歪
