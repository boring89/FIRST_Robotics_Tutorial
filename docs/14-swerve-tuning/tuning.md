# 調整參數

--8<-- "alpha-warning.md"

## 這頁學什麼

- 調整的順序：轉向 → 驅動的 Feedforward → 驅動的 P
- 用 AdvantageScope 比較目標和實際的角度、速度
- 確認最高速度和電流限制

## 觀念

### 為什麼先調轉向

驅動的速度要在**輪子指向正確**的時候才有意義。轉向還在抖、還跟不上，量到的速度就不準，調驅動也調不好。所以一定是：

1. **轉向的 P**（必要時加 D）
2. **驅動的 kS、kV**（Feedforward）
3. **驅動的 P**

這和[第 8 章](../08-control/feedforward.md)講的「Feedforward 是主角，P 只是修正」是同一件事。

### 要看哪些數值

[上一頁](onboard-pid.md) 加的 `log()` 會送出每個模組的四個數值：

| 名稱 | 意思 |
| --- | --- |
| `Swerve/FrontLeft/AngleDegrees` | 左前模組實際的角度 |
| `Swerve/FrontLeft/TargetAngleDegrees` | 左前模組的目標角度（`optimize` 之後） |
| `Swerve/FrontLeft/Velocity` | 左前模組實際的速度，m/s |
| `Swerve/FrontLeft/TargetVelocity` | 左前模組的目標速度（`cosineScale` 之後） |

在 AdvantageScope 開一個**折線圖**，把同一個模組的目標和實際值放在一起，就能看出追得好不好。

## 步驟

### 1. 轉向的 P

機器人**架高**。在 AdvantageScope 畫出 `AngleDegrees` 和 `TargetAngleDegrees`。

1. 從 `STEER_KP = 0.3` 開始
2. 快速把左搖桿從「往前」推到「往左」，目標角度會從 0 跳到 90 度
3. 看實際角度追上目標的樣子：

| 看到的情況 | 調整 |
| --- | --- |
| 很慢才到、慢慢靠近 | kP 加大（例如每次 ×1.5） |
| 很快到，但超過目標再回來（過衝） | kP 減小，或加一點 D（例如 `STEER_KD = 0.005`） |
| 到了之後一直小幅抖動 | kP 太大，減小 |
| 停在差一點點的地方 | 摩擦力太大，P 推不動。kP 稍微加大 |

好的轉向：90 度的變化在 **0.1～0.2 秒**內到位，沒有明顯的過衝。

### 2. 驅動的 kV、kS

機器人放在**地上**，先把 `DRIVE_KP` 設為 0，只靠 Feedforward。

1. 推左搖桿往前約一半，直線開幾公尺
2. 畫出 `Velocity` 和 `TargetVelocity`
3. 實際速度**比目標低**：kV 加大；**比目標高**：kV 減小
4. 換成很慢的速度（搖桿推一點點）再試。很慢時輪子不太動、或總是比目標慢：kS 加大

[硬體與常數](../13-swerve-drive/hardware.md#估計驅動的-feedforward) 估的 kV ≈ 0.81，實際的值通常會差不多，但 kS 一定要在地上量，因為它是**摩擦力**，架高時和放在地上完全不一樣。

!!! tip "小技巧：用 SysId"
    [第 8 章的 SysId](../08-control/sysid.md) 可以量出準確的 kS、kV、kA。Swerve 的做法是讓四個輪子都朝前（例如用 X 字鎖定的寫法，但四個角度都是 0），再對驅動馬達跑 SysId。完整的做法在[第 20 章](../20-swerve-calibration/drive-sysid.md)。

### 3. 驅動的 P

把 `DRIVE_KP` 加回來（例如 0.1），P 負責修正 Feedforward 沒算到的部分（例如推到東西、上坡）。開車時用力推一下機器人，看速度掉下來之後多快恢復。P 太大時，速度會在目標附近抖動，聽到馬達有高頻的聲音。

### 4. 確認最高速度

1. 在空曠的地方，搖桿推到底直線開
2. 看 `Velocity` 最高到多少

如果實際最高速度明顯低於 `MAX_SPEED`（例如只有 4.0 m/s），把 `MAX_SPEED` 改成實際的值。不然搖桿從 90% 推到 100% 時，目標速度增加了，但馬達已經到極限，速度不會再變；而且 Desaturate 會以為還有空間，不會幫你縮小速度，旋轉時方向就不準了。

### 5. 電流限制

| 馬達 | 這幾章的值 | 為什麼 |
| --- | --- | --- |
| 驅動（定子電流） | 60 A | 太大會讓輪子打滑、電池電壓掉太多（Brownout）；太小加速會變慢 |
| 轉向（Smart current limit） | 30 A | 轉向不需要很大的力，限制低一點可以保護 NEO |

八顆馬達同時加速時，電流加起來很可觀。比賽中如果 Driver Station 出現 Brownout 的警告，先降低驅動的電流限制。

## 常見錯誤

!!! bug "常見錯誤：架高時調驅動的 Feedforward"
    輪子離地時沒有負重，用很小的電壓就能轉很快，調出來的 kV 會偏低、kS 幾乎是 0。放到地上就跑不到目標速度。**驅動一定要在地上調**。

!!! bug "常見錯誤：四個模組只看一個"
    只看左前調好了，結果右後的 CANcoder 鬆了、或是那個模組的齒輪比較緊。調完之後**四個模組都看一次**，確認它們的表現差不多。

## 小練習

1. 照上面的步驟調你們的 Swerve，記錄最後的 `STEER_KP`、`STEER_KD`、`DRIVE_KS`、`DRIVE_KV`、`DRIVE_KP`。
2. 量量看實際的最高速度。和[硬體與常數](../13-swerve-drive/hardware.md#最高速度) 算的理論值差多少？為什麼會有差距？
3. 把 `STEER_KP` 調到明顯太大，在 AdvantageScope 上看會發生什麼事。記下這個值，以後就知道「太大」長什麼樣子。

??? question "第 2 題參考答案"
    實際值通常比理論值低 5～15%。理論值用的是馬達**空轉**的轉速，但實際上：

    - 機器人有重量，輪子和地面、齒輪之間都有摩擦
    - 電池在大電流時電壓會下降，不是一直維持 12 V
    - 電流限制讓馬達在加速時無法輸出全部的扭力
