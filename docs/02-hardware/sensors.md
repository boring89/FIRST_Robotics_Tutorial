# 感測器

--8<-- "alpha-warning.md"

## 這頁學什麼

- 為什麼機器人需要感測器
- FRC 常見的感測器種類，以及它們接在哪裡
- 每種感測器能回答程式的什麼問題

## 觀念

### 機器人怎麼知道自己的狀態

只靠馬達，機器人是「閉著眼睛」在動：程式叫馬達轉 2 秒，但不知道實際走了多遠。**Sensor（感測器）** 讓程式知道機器人現在的狀態，才能做出準確的動作。

每一種感測器都在回答一個問題：

| 程式想知道 | 用什麼感測器 |
| --- | --- |
| 輪子 / 手臂轉了多少？轉多快？ | Encoder（編碼器） |
| 機器人面向哪裡？ | Gyro / IMU（陀螺儀 / 慣性測量單元） |
| 機構到底了沒？ | Limit switch（極限開關） |
| 遊戲物件進來了沒？ | Beam break（光遮斷感測器）、距離感測器 |
| 機器人在場上的哪裡？目標在哪？ | 相機 + 視覺處理 |

### Encoder（編碼器）

編碼器量測**轉動的角度和速度**，是 FRC 最重要的感測器。

- **內建編碼器**：無刷馬達（NEO、Kraken 等）都有內建編碼器，資料透過馬達控制器回傳，不用另外接線。
- **外接編碼器**：裝在機構的轉軸上，量測機構本身的角度。

編碼器分成兩種：

- **Relative encoder（相對式編碼器）**：只知道「從開機到現在轉了多少」，斷電後歸零。
- **Absolute encoder（絕對式編碼器）**：隨時知道目前的絕對角度，斷電重開也一樣。Swerve 的轉向模組一定要用絕對式編碼器。

=== "REV"

    - **Through Bore Encoder**：可以接到 SPARK MAX / SPARK Flex，同時提供相對式和絕對式資料

=== "CTRE"

    - **CANcoder**：直接接在 CAN 上的絕對式編碼器，常用在 Swerve 轉向模組

Motioncore 上也有 3 個 quadrature（正交）編碼器埠，可以接外接編碼器做里程計。

### Gyro / IMU（陀螺儀 / 慣性測量單元）

IMU 量測機器人的**轉向和加速度**。最常用到的是 **Heading（朝向）**：機器人現在面向場地的哪個方向。做 Swerve 的場地座標控制、自動階段的路徑跟隨都會用到。

- **Systemcore 內建 IMU**：2027 起主控制器就內建 IMU，程式要設定 Systemcore 在機器人上的安裝方向
- **外接 IMU**：例如 CTRE 的 **Pigeon 2**，接在 CAN 上

### 數位感測器

**Limit switch（極限開關）** 和 **Beam break（光遮斷感測器）** 只會回報「是 / 否」兩種狀態，接在 Systemcore 的 **Smart IO** 上：

- 極限開關：手臂轉到底時觸發，程式就讓馬達停下，避免機構撞壞
- 光遮斷感測器：遊戲物件擋住光線時觸發，程式就知道「拿到東西了」

!!! warning "注意：alpha 與 beta 版 Systemcore 的接法不同"
    alpha 版 Systemcore 的 IO 腳位內建下拉電阻 (pull-down)，極限開關要接在訊號腳和 +3.3V 之間；beta 版改成上拉電阻 (pull-up)，和 roboRIO 一樣。手上的是哪一版，接線前要先確認。

### 相機與 Coprocessor（協同處理器）

視覺處理需要大量運算，通常不在 Systemcore 上做，而是交給：

- **Limelight**：相機和處理器做在一起的產品，設定簡單
- **PhotonVision**：開源的視覺軟體，裝在 Orange Pi 等協同處理器上，搭配一般 USB 相機

它們最常拿來辨識場上的 **AprilTag**，算出機器人在場上的位置。詳細內容在 [第 10 章 視覺](../10-vision/index.md)。

## 常見錯誤

!!! bug "常見錯誤：以為相對式編碼器記得位置"
    手臂用相對式編碼器，開機時的位置就是 0。如果開機時手臂不在固定的起始位置，程式算出來的角度全部會錯。解法是開機時把機構放在固定位置，或改用絕對式編碼器。

!!! bug "常見錯誤：IMU 安裝方向沒設定"
    Systemcore 斜放或直立安裝，卻沒在程式裡設定方向，讀到的 Heading 會不對，Swerve 會往奇怪的方向跑。
