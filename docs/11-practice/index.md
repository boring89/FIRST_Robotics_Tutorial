# 第 11 章 實戰

--8<-- "alpha-warning.md"

程式寫好、能在練習場跑，只是第一步。真正的比賽會遇到時間壓力、陌生的場地網路、被撞壞的機構，還有「明明昨天還好好的」的各種問題。這章整理程式組在**團隊合作**和**比賽現場**需要的技能。

## 這章學什麼

- 用 Git 管理程式碼、和隊友分工
- 記錄比賽資料，用 AdvantageScope 回放、找出問題
- 上場前、比賽中、下場後要檢查什麼
- 機器人出問題時，怎麼有系統地找出原因

**需要先讀**：前面幾章的內容都會用到，特別是[第 4 章 部署與除錯](../04-robot-basics/deploy-debug.md)。

## 比賽時程式組在做什麼

| 時間 | 程式組的工作 |
| --- | --- |
| **出發前** | 確認比賽用的程式版本、所有筆電都能離線編譯（[第 3 章延伸學習](../03-setup/further.md#比賽前的離線準備)） |
| **每場比賽前** | 跑一次檢查清單、選好自動程式、確認聯盟顏色 |
| **比賽中** | 在駕駛站旁邊注意 Driver Station 的訊息 |
| **每場比賽後** | 下載 log、和駕駛討論有什麼問題、在下一場之前修好 |
| **每天結束** | 把當天的修改整理好、commit、記錄做了什麼 |

!!! tip "小技巧：比賽中少改程式"
    比賽期間時間很少、壓力很大，最容易寫出新的錯誤。**只修會讓機器人無法比賽的問題**，其他的想法先記下來，比賽結束後再改。每次修改都要先在 pit 測試過才上場。
